# Phase 11 Paper Trading / Future Lockbox 审计

## 结论

Phase 11 的工程实现已经完成，但前瞻统计验证尚未开始。`candidate_bundle_v1` 的生产序列化模型固定在提交 `631ca494e5d5f829bd353134482e80812ae62129`：HGB raw、P4 constrained、20bp 往返成本、10%成交量参与率、T+1与整手规则均未改变。模型使用截至2026-09-30的PIT数据，经5个交易日标签隔离后包含318,300条训练样本、1,061个周频截面和30维设计矩阵；模型文件SHA-256为`6ae5ef99d7f4b7a53da79dfdc146d9d968f55b03d088096677eb028d9d924849`。

激活日固定为2026-10-21。2026-10-20只记录了一次`NOT_ACTIVE`运营事件，没有信号、订单、成交或业绩观测。因此当前成功前瞻观测为0，不能声称策略获得前瞻验证、paper业绩或实盘验证。

## 已实现控制

- 日度任务只能处理Asia/Shanghai当日；传入其他日期会登记为`REJECTED_BACKFILL`，不能形成成功观测。
- 每个运行创建不可覆盖目录，先写数据文件，最后写`run.json`完成标记；运行日志逐条链接前一事件SHA-256。
- 输入记录因子、行业、规模、行情文件及模型包哈希；每条信号可以追溯到数据版本、配置版本、Git提交和模型版本。
- 新目标使用冻结HGB raw分数、Top-200/400缓冲、行业±3%、|size-z|≤0.10、单股≤1%与30%单边换手约束；不可行时只能使用显式carry-forward repair，不允许静默放宽。
- 账户逐日重放股数订单、T+1、成交量上限、涨跌停/停牌、成本、现金、持仓和NAV；开放订单在日终保持活动，供下一真实交易日继续处理。
- 失败、缺失、非交易日与未激活日期不会静默删除；若此前交易日完全没有任何运行记录，后续交易日会被门禁阻断。
- Future lockbox只允许查看数据覆盖、缺失率、任务状态和账本对账；收益、Sharpe、回撤、IC及相对基准表现继续封存。
- Phase 11.1补齐了前瞻数据供应：`quant-forward-data` 在独立`forward_*`命名空间内，对日历、已完成周的PIT证券快照、月度行业快照和当前活跃股票行情执行自然键增量合并，再只对变更证券物化质量、因子和标签。paper runner在训练截止日后直接读取这些逐证券PIT文件，不再依赖冻结年度研究面板。历史表恢复至2026-09-30后，全仓冻结审计为496 PASS / 46 WARN / 0 FAIL。
- 周频信号门控使用向前预取的交易日历确认`W-FRI`周期真正结束；周中不能因为“今天暂时是本周最后一个已下载日期”而提前调仓。无初始信号时记录`NO_SIGNAL`，不计为成功前瞻观测。

## 运行责任

激活后应先执行`quant-forward-data all`，确认供应商错误为0、最新行情日期和覆盖率达标，再执行`quant-paper-trading run-daily`。运营人员可以查看运行健康，但不能打开future lockbox的中途绩效。若paper结果触发任何策略修改，必须停止旧版本、登记其已被用于变更，冻结新的候选ID并重新开始前瞻期。
