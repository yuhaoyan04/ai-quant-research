# Phase 5 执行引擎基线审计与差异清单

## 审计范围

审计对象为 `daily_execution.py`、`constrained_portfolio_daily_execution.py`、
`execution_constraints.py`、交易成本模块、对应配置、测试和冻结实验。Phase 5 不改变信号、模型、
目标权重或 20bp 成本，只升级目标权重到模拟成交和账户状态之间的执行层。

## 实施前基线

旧日频引擎已经做到：唯一日频净值时钟、收益后收盘成交、停牌和涨跌停受阻、剩余股数逐日重试、
新目标覆盖旧剩余订单、fill 级费用分摊，以及 `NAV = cash + positions` 的日级检查。

但旧 `pending: dict[instrument, shares]` 不是订单账本。它不能保存订单生命周期、部分成交原因、
过期/替换事件、T+1 可卖库存、整手约束、成交量参与率、逐日持仓快照或公司行动调整。旧价格还是
从 1 开始按供应商涨跌幅递推的合成价格，因此不能用于人民币股数、成交量和现金容量的统一模拟。

## 差异与优先级

| 优先级 | 实施前差异 | Phase 5 处理 |
|---|---|---|
| P0 | 无订单 ID、事件和终态 | 新增 NEW/PARTIALLY_FILLED/FILLED/BLOCKED/CANCELLED/EXPIRED/REPLACED 状态机 |
| P0 | 无 T+1 可卖库存 | 分离 `available_shares` 与 `unsettled_shares`，fill 记录成交前可卖数量 |
| P0 | 无成交量部分成交 | 使用 10% 日成交量参与率，剩余订单重试并按 5 个交易日过期 |
| P0 | 无人民币现金/原始价格统一账本 | 1 亿元初始现金、未复权收盘成交、fill 费用和逐日 NAV 守恒 |
| P1 | 无 A 股数量规则 | 主板 100 股整手；科创板最低 200 股、其后 1 股递增；零股仅清仓 |
| P1 | 公司行动会导致原始价格断点 | 使用可审计的价值保持因子代理；明确不等同官方公司行动数据 |
| P1 | 未成交原因只能从布尔标记猜测 | 分别记录停牌、涨停、跌停、成交量、现金、T+1 和缺失行情 |
| P2 | 无盘口、bid/ask 和队列数据 | 保持未实现并明确披露，禁止将日线模拟描述为真实撮合 |
| P2 | 未覆盖 IPO 无涨跌幅窗口与券商细节 | 保持已知限制，待可靠参考数据或券商数据后另建实验 |

## 规则依据与边界

主板竞价买入通常为 100 股或其整数倍，零股卖出需一次处理；科创板申报最低 200 股、超过部分可
按 1 股递增。普通 A 股买入后在交收前不可卖出，因此账本执行 T+1 可卖约束。规则实现只用于本项目
覆盖的沪深 A 股日线近似；ETF、债券、回转交易品种和盘中订单簿不在范围内。

## 验收口径

- 两个场景共享冻结 raw HGB 目标、1,387 日时钟和 C0 20bp 成本；
- 每笔 fill 可追溯到订单，费用之和等于日账本费用；
- 现金非负、持仓非负、卖出不超过成交前可卖股数；
- 每日 `NAV = cash + market value`，成交后 NAV 仅减少费用；
- 订单替换、部分成交、过期和受阻原因不被静默删除；
- 历史结果属于已查看 historical OOS 诊断，不构成新的独立证据。
